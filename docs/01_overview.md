# 概要

[目次に戻る](README.md)

## 概要・目的

筋力トレーニング・運動の内容（種目・重量・回数・セット）を記録して進捗を確認でき、その記録を写真付きで投稿して仲間と励まし合える Web アプリ **Workout Log** を開発する。講義の課題として個人で開発し、AWS に公開する。AWS の環境は動作確認・発表のときだけ作り、終わったら消す（[AWS 構成](12_aws-architecture.md)）。

記録アプリとしての使いやすさ（ジムで片手で素早く入力できる、休憩タイマーがある、成長がグラフで分かる）と、SNS としての続けやすさ（仲間の頑張りが見える、いいね・コメントがもらえる）を両立させることを目指す。

スマートフォンでの利用を中心に考え、ホーム画面に追加してアプリのように使える PWA にする。

**MVP のゴール**

- ユーザーが登録・ログインし、トレーニングを種目・重量・回数・セット単位で記録できる
- よく行うメニューを保存し、メニューから記録を始められる。セット間の休憩をタイマーで計れる
- 種目ごとの重量の推移と自己ベスト、体重の推移をグラフで確認できる
- トレーニング記録を添付した、写真付きの投稿ができる。フォロー・いいね・コメントで交流でき、その通知を受け取れる
- AWS に公開し、動作確認・発表のときにスマートフォンのブラウザから使える

## 前提条件・想定利用者

- 開発・運用は 1 名。利用者は講義の関係者（数人〜数十人）を想定する
- 不特定多数向けの運用に必要な機能（ブロック・通報・管理画面・凍結、パスワードリセット、Google ログイン、レート制限）は MVP の対象外とし、Could にする。メールアドレス確認と退会は、本人のデータを守るための最低限の機能として MVP に含める
- 対応言語は日本語のみ。重量の単位は kg のみ
- 技術スタックは、同じ開発者による別の課題「SNSアプリ」（React + Spring Boot + PostgreSQL の分離型）とは変え、Next.js のフルスタック構成＋MySQL にする（[技術スタック](07_tech-stack.md)）

| ロール | 説明 | できること |
| --- | --- | --- |
| ゲスト（未ログイン） | アカウントを持たない訪問者 | 全体タイムライン・投稿詳細・プロフィールの閲覧、新規登録、ログイン |
| 一般ユーザー（メール未確認） | 登録したがメールアドレスを確認していない利用者 | トレーニング・体重の記録と閲覧（本人のみ）、メニュー作成、進捗の確認、閲覧、ユーザー検索、プロフィール編集、退会 |
| 一般ユーザー（メール確認済み） | メールアドレスを確認した利用者 | 上記に加えて、投稿、コメント・返信、いいね、フォロー、通知の確認 |

### データの公開範囲

| データ | 見られる人 |
| --- | --- |
| トレーニング記録（ワークアウト・セット）、メニュー、体重・体脂肪率、自己ベスト・グラフ | 本人だけ |
| 投稿に添付したワークアウト | 投稿を見られる全員（添付した 1 件だけが、投稿を通して公開される） |
| 投稿・コメント・プロフィール・フォロー関係 | 全員（ゲストを含む） |
| プロフィールの実績（総トレーニング日数など、集計値のみ） | 全員 |

## リリース計画・スコープ外

1. **MVP**：[機能要件](02_functional-requirements.md)の Must をすべて実装し、AWS に公開する
2. **次リリース**：Should（自己ベスト更新時の投稿の下書き、ワークアウト・メニューの複製）
3. **将来**：Could（ランキング・チャレンジ、ストリーク・バッジ、CSV エクスポート、ブロック・通報など）。講義用に MVP から外した、不特定多数向けの運用機能もここに含む

**今回は対象外**

- ダイレクトメッセージ
- 動画投稿
- 投稿の編集
- 非公開（鍵）アカウント
- ネイティブアプリ（iOS / Android）
- ウェアラブル端末・ヘルスケアアプリ（Apple ヘルスケア、Google Fit など）との連携
- 食事・カロリーの記録
- AI によるメニュー提案
